# 首版设计：可修订的决策账本

## 模块边界

```text
用户 CLI → Store：建立/修改任务、确认/修改/删除记忆
                ↓
DeepAgents → TaskWorkflow：首步评估；需澄清则程序结束本轮
                ↓ ready
           受限工具：读任务/查来源/存结论/提出澄清或记忆
                ↓
SQLite → 结论修订历史 + 事件记录 → Markdown 报告
```

`domain.py` 定义数据校验；`store.py` 负责事务；`tools.py` 关闭在指定任务上，不能访问别的任务 ID；`agent.py` 构图；`workflow.py` 管理评估与等待状态；`runtime.py` 限制执行并记录；`evidence.py` 只用于用户导入；`report.py` 和 `review.py` 不调用模型。

`scenarios.py` 定义内部知识库选型的任务模板，默认不附带资料。只有显式选择 example_materials 才从包内 assets 导入虚构来源；安装 wheel 后不依赖仓库 examples 目录。`scenario_demo.py` 使用同一模板、真实图和预设模型走完澄清到变更交接，阻断网络，不修改通用工具的权限。

## 评估与澄清状态

每次新运行先只向模型暴露 `assess_task`，并强制选择该工具。入口消息提供有界任务快照，不必先额外调用 get_task。评估工具要求明确的 ready/needs_clarification 状态、原因和问题列表。

- ready：必须没有问题，随后开放业务工具。评估标识绑定当前运行，不能拿旧运行的 ready 跳过入口。
- needs_clarification：必须至少有一个问题；Store 原子保存状态和问题，before_model hook 直接跳到结束，由程序生成追问文本，不再请求模型。
- 后续发现缺口：request_clarification 同样设置等待状态；继续保存结论会被拒绝。
- 再次运行等待中的任务：直接返回既有问题，模型调用为零。只有用户实际修改约束、递增版本，才重置为 unassessed；模型不能自行清除等待。
- 尚未评估就直接生成最终答案：拒绝，不伪装为成功。

这是显式工作流控制，不是自动识别缺失条件的语义证明；模型仍可能错误选择 ready。任务、来源和记忆仍需用户检查。不提供运行中挂起的 checkpoint 恢复。

## 工具参数与错误边界

save_claim 的工具 schema 根据当前任务生成，depends_on 必须显式填写，元素是当前约束键的枚举，不接受 claim_id/source_id。空列表必须附 independence_reason；即使说明了独立性，约束变化时仍走保守复核。枚举只能防止非法键，不能证明依赖完整或语义正确。

Schema 错误返回结构化 invalid_arguments；已知可修正的来源、引用或结论 ID 错误使用 RecoverableToolError，由工具适配层转成 ok=false、retryable=true，并返回合法约束键。模型可以在原调用预算内修正，适配层不自动重试或放宽校验。

未捕获的 DomainError（例如契约过期、容量限制）、预算错误及运行时工具越权仍终止运行。不是 catch-all 异常吞并。单个写入仍是事务，整轮工具调用不是一个可整体回滚的事务。

## 依赖变更规则

- 更新已有约束：声明依赖该键的结论进入 needs_review。
- 新增约束：已有结论全部保守进入 needs_review。
- 空依赖（新写入必须说明原因，旧记录仍可读取）：约束改变时保守复核。
- 相同值：不增加任务版本，不触发复核。
- 不受影响的结论保留原修订和形成时的约束版本，不假装重新核验过。
- 修订用原 claim_id，新文本与证据形成新 revision，旧历史不被覆盖。
- 若运行入口存在 needs_review，工具适配层固定本轮复核 ID 集合；即使最后一个待复核项已经更新，也不能顺带重写入口时未受影响的旧结论，而是返回 outside_review_batch。可新增真正的新发现。全部复核完成后的新运行不再受旧批次限制；这不是永久冻结结论，也不能阻止模型错误创建重复条目。
- 每个运行捕获一个 contract_version；任务中途改变时拒绝后续 claim 保存。

这不是因果推断器。depends_on 由模型声明，遗漏可能导致漏标。新增键的全量复核是保守退路；需要时用户应人工检查报告全部条目。

## 变更交付报告

`review` 是从账本计算的只读视图，不是新一轮模型总结。默认基线为上一契约版本，也可指定更早版本；没有发生约束变更时应使用 report。

每条结论取基线版本及以前的最后一个历史修订作 before，再与当前 after 比较：仍标 needs_review 时优先显示待复核；没有 before 为新增；revision 不同为修订；否则为保留。文本相同但 revision 增加也算修订，不伪装为没有改写。JSON 与 Markdown 使用同一份结构化视图。

视图保留原 ID、契约版本、前后文本、依赖、证据与局限，单独展示未解决事项；无结论、未评估和等待澄清不会被展示成完成交付。账本复核已记录也不等于人工批准。同一契约版本内的多次写入不支持任意时刻回放，新增来源也不会自动触发失效。

## 证据完整性不等于真实性

来源保存内容快照、类型、origin 和 SHA-256。claim 必须指向本任务来源，并使用精确子串，程序记录字符区间。只表示引用可定位，不证明文本权威或支持结论。

本地文件以相对 origin 保存，避免默认泄露用户绝对目录。Tavily 内容只作摘要；不直接请求第三方 URL。

## 记忆

每条仅有一个项目 scope；待确认项不进入模型 get_task。确认是 CLI 用户动作，修改后重新待确认；删除后不再加载。不把记忆直接复制到契约，不允许它覆盖当前用户要求。

事件中不存记忆正文的专门变更副本，但以往模型上下文可能已包含该内容。删除的语义为停止后续使用，不是彻底清理所有历史副本。

## 执行配置

本应用仅支持同步、单主图、少量工具。默认 general-purpose 被禁用，摘要 middleware 被排除，防止隐藏的摘要模型调用超出主循环计数。待办 middleware 同样排除，避免简单决策任务为维护 write_todos 增加调用。任务过长时失败并要求拆分，而不是自动无限扩展上下文。

SDK 必需文件/子 Agent scaffolding 保留；公开模型菜单移除其高层工具，额外 allowlist 在工具执行边界阻止越界。注册 harness profile 作用于本 CLI 进程中指定 provider:model，不修改 SDK 文件。

trace 是模型/工具边界记录，不是每个内部图节点的完整树；parent_run_id 可能没有对应节点记录。单次 run 的 execution_id 用于聚合事件。

## 验收范围

标准库 unittest + 零网络 scripted model，覆盖约束失效、精确引用、修订、记忆确认、路径边界、预算和真实 DeepAgents 工具循环。真实模型输出质量需要用户使用中检查；本次不跑模型训练、效果对照或实验任务集。
